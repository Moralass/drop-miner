# Drop Miner — архитектура, запуск и дорожная карта

Десктоп-приложение (Tauri 2 + React) для планирования Twitch Drops на нескольких аккаунтах, с подпиской (Stripe), лицензиями, админ-панелью и ИИ-помощником.

## 1. Принцип продукта

Drop Miner **не имитирует просмотр**. Он:
- ведёт каталог кампаний (редактируется в админке),
- считает, какой аккаунт что успевает пройти до дедлайна,
- открывает **настоящие** стримы в изолированных окнах-профилях (звук выключен, качество 160p — это обычные настройки плеера Twitch).

Не реализовано намеренно: фейковые heartbeat-запросы, эмуляция зрителей, обход проверок Twitch. Это нарушает правила платформы и ведёт к бану аккаунтов. Пользователь сам отвечает за соблюдение правил Twitch; в лендинге и приложении нужен дисклеймер (есть в футере лендинга).

## 2. Архитектура

```
┌──────────────────────┐        HTTPS         ┌────────────────────────┐
│ Desktop (Tauri)      │ ───────────────────► │ API (Fastify, Node 22) │
│ React UI + Rust core │   JWT, /v1/*         │ auth · license · AI    │
│ профили = data_dir   │                      │ billing · admin        │
└─────────┬────────────┘                      └───────┬────────┬───────┘
          │ webview (twitch.tv)                       │        │
          ▼                                           ▼        ▼
   Окна аккаунтов                               PostgreSQL   Stripe / Anthropic API
```

| Слой | Решение | Почему |
|---|---|---|
| Десктоп | Tauri 2, Rust | лёгкий (~10 МБ), нативные webview, изоляция профилей через `data_directory` |
| UI | React + Vite + Zustand | быстрый старт, стейт хранится локально (persist) |
| Бэкенд | Fastify + Zod + Prisma | типобезопасность, быстрый, валидация на границе |
| БД | PostgreSQL 16 | транзакции, индексы, легко масштабируется (read-replica, pgbouncer) |
| Платежи | Stripe Checkout + Customer Portal + webhooks | тариф определяется только по webhook, не по клиенту |
| ИИ | Anthropic API (модель в `AI_MODEL`) | совет по расписанию, лимиты по тарифу |

### Безопасность (что уже заложено)
- Пароли: argon2id; одинаковый ответ на «нет пользователя»/«неверный пароль»; строгий rate-limit на `/auth/*`.
- JWT 7 дней; роль ADMIN **перепроверяется по БД** на каждом админ-запросе.
- Zod-валидация всех входов; `helmet`, CORS по белому списку.
- Webhook Stripe — проверка подписи по сырому body.
- Rust-команды валидируют `account_id` и `channel` (без инъекций в URL/пути).
- CSP в `tauri.conf.json`; тариф на клиенте — только для UX, реальные лимиты (устройства, ИИ) проверяются на сервере.
- Аудит-лог админ-действий.

### Модель лицензий
`free` (без подписки) → **1 аккаунт**, 1 устройство · `pro` → 5 аккаунтов, 2 устройства, ИИ 50/день · `team` → 20 аккаунтов, 5 устройств, ИИ 200/день.

Лимит аккаунтов **проверяется на сервере** (`POST /v1/license/accounts`, транзакция Serializable), а не только в интерфейсе: сервер хранит id и подпись каждого добавленного аккаунта (пароли и токены Twitch к нам не попадают). Правка клиента лимит не обходит. Если подписка закончилась, активными остаются самые старые аккаунты в пределах лимита, остальные блокируются, но данные не удаляются и возвращаются после продления. Для работы приложения нужен бесплатный аккаунт Drop Miner (иначе лимит нечем привязать).

### Активация подписки ключами
Основной способ получения платного тарифа — ключ вида `DD-XXXX-XXXX-XXXX-XXXX`.
- **Генерация:** админка → «Ключи активации» (тариф Pro/Team, срок в днях или бессрочно, пачка до 200, заметка). Открытые ключи показываются **один раз** (копирование / скачивание .txt), в БД лежит только HMAC-SHA256 с секретом `KEY_PEPPER`.
- **Формат:** 80 бит случайности, алфавит Crockford (без I/L/O/U), ввод прощает регистр, пробелы и дефисы. Перебор нереалистичен; `POST /v1/license/redeem` дополнительно ограничен 5 запросами в минуту.
- **Правила активации** (всё в одной Serializable-транзакции, ключ не сгорает при отказе):
  - нет подписки / подписка истекла → тариф ключа, отсчёт с сегодня;
  - тот же тариф уже активен → срок **продлевается** (добавляется к текущему окончанию);
  - ключ выше текущего тарифа → переход на него, остаток старого срока не переносится;
  - ключ ниже активного тарифа, активная подписка Stripe или бессрочная лицензия того же уровня → отказ.
- **Отзыв:** только неактивированные ключи. Уже активированный тариф снимается в админке («Пользователи» → смена тарифа), действие пишется в аудит.
- **Stripe** остаётся в коде и выключен в интерфейсе (`VITE_STRIPE_ENABLED=false`). Включите флаг при сборке, если захотите принимать карты.
- ⚠️ **`KEY_PEPPER` менять нельзя** после выдачи ключей: все невыданные ключи перестанут проходить проверку. Храните его в секрет-хранилище и делайте бэкап вместе с БД.
- Продавать ключи можно любым способом (магазин, Telegram-бот, ручная выдача). Ссылку на магазин задаёт `VITE_BUY_URL` (кнопка «Где купить ключ»). Автовыдача ключей после оплаты — в планах (v0.4).

## 3. ИИ-функции
1. **Совет по расписанию** (`POST /v1/ai/plan-advice`) — реализовано: аккаунты + кампании → рекомендация по порядку прохождения.
2. Дальше: дайджест новых кампаний («что стоит проходить на этой неделе»), объяснение причин, почему награда не засчитана (по логам окна).

## 4. Запуск

### Бэкенд (локально)
```bash
cd backend
cp .env.example .env        # заполните JWT_SECRET (32+ символов), Stripe, Anthropic
npm install
npx prisma migrate dev --name init   # при обновлении с v0.3: --name v04 (новые поля blockedAt/keyId)
npm run dev                 # http://localhost:4000/health
```
Переменные окружения (`backend/.env`):
- `DATABASE_URL`, `JWT_SECRET` (32+ символов) — обязательны.
- `KEY_PEPPER` — секрет для HMAC хэшей ключей. **После выдачи первых ключей менять нельзя** — все выданные ключи перестанут находиться.
- `ADMIN_EMAIL`, `ADMIN_PASSWORD` — первый администратор создаётся при старте (если его ещё нет).
- `TWITCH_CLIENT_ID`, `TWITCH_CLIENT_SECRET` — для мониторинга эфиров (app access token, только на сервере). Без них мониторинг показывает «N/A».
- `LOG_LEVEL`, `CORS_ORIGINS`, Stripe/Anthropic — по необходимости.

### Stripe
1. Создайте два recurring-прайса (Pro, Team), впишите `STRIPE_PRICE_*`.
2. Webhook → `https://api.<домен>/v1/billing/webhook`, события: `customer.subscription.created|updated|deleted`; секрет в `STRIPE_WEBHOOK_SECRET`.
3. Локально: `stripe listen --forward-to localhost:4000/v1/billing/webhook`.

### Продакшн
```bash
docker compose up -d --build     # db + api; миграции применяются при старте контейнера
```
Поставьте перед API Caddy/nginx с TLS (домен `api.<домен>`), включите бэкапы Postgres (pg_dump по крону или managed-БД).

### Десктоп
```bash
cd desktop
npm install
npm run tauri icon path/to/icon.png   # один раз: сгенерировать иконки
npm run tauri dev
npm run tauri build                   # установщики под текущую ОС
```
Для релиза: подпись кода (Windows — EV/OV сертификат, macOS — Developer ID + notarization) и автообновления через `tauri-plugin-updater`.

### Админка
`admin/index.html` — статическая страница (Cloudflare Pages и т.п.), адрес API задаётся `?api=https://api.<домен>`. Добавьте её origin в `CORS_ORIGINS`. Войти может только пользователь с ролью ADMIN.

### Лендинг
Статические файлы из `landing/`: `index.html`, юридические страницы (`terms.html`, `privacy.html`, `refund.html`), `style.css`, `logo.png`, `billing/*` (возврат из Stripe, пока выключен). Хостинг: Cloudflare Pages / Netlify / любой статический. Замените домен `dropminer.app` и добавьте `og.png`, подайте sitemap в Search Console. **Юридические тексты написаны как черновик: перед публичными продажами их должен посмотреть юрист** (особенно возврат, срок хранения журналов и ответственность).

## 6. Известные ограничения (честно)
- **Прогресс считается локально**: +1 минута, когда аккаунт активен, назначена кампания, канал в эфире (по данным Twitch Helix) и окно стрима реально открыто. Официального API для чтения дропов произвольного пользователя нет, поэтому в приложении это подписано как «не подтверждено Twitch». Награды как «получено» приложение не отмечает.
- **Мониторинг эфиров** идёт через наш сервер (Helix Get Streams, app token, кэш, батчи до 25 логинов). Без `TWITCH_CLIENT_ID/SECRET` статус «N/A». Пользовательские токены Twitch на сервере не хранятся и не запрашиваются; вход в Twitch — только в изолированном окне-профиле.
- **Не делаем**: накрутку просмотров/heartbeat без реального плеера, обход правил платформы. **Не реализовано**: Kick (нет подтверждённого API/доступов), серверный Twitch OAuth.
- **Не проверено в среде разработки**: компиляция Rust (`cargo`), Prisma-зависимые маршруты и полный `tsc` бэкенда (движок Prisma не скачался), реальный Twitch API, установщик, автообновление. Проверено: `desktop`: `tsc` + 19 unit-тестов; `backend`: 14 unit-тестов (ключи, Twitch-клиент с подменой fetch).
- **Обложки игр**: берутся из каталога Twitch (Helix Get Games, `box_art_url`) через `/v1/channels/games`, кэш 24 ч; свои копии картинок мы не храним. Без настроенного Twitch API показывается нейтральная заглушка. Не проверено на реальных ключах.
- **Интерфейс приложения**: чёрно-синяя тема, боковое меню (Главная, Аккаунты, Drops, Мониторинг, Уведомления, Подписка). Проверен только скриншотом в обычном браузере с подставленными ответами сервера; в самом окне Tauri и с реальным Twitch не запускался. Кнопка «Начать» открывает окно стрима и закрепляет кампанию за свободным аккаунтом, «Остановить» закрывает окно.
- Каталог кампаний ведётся вручную через админку; автоимпорт — позже.
- Токен приложения хранится в localStorage (Tauri webview). Для усиления — keyring (v0.5).
- Админка (`admin/index.html`) — статическая страница поверх `/v1/admin/*`; ограничьте доступ (IP-allowlist / Cloudflare Access), добавьте 2FA.
- Один человек может завести несколько учёток Drop Miner ради бесплатных слотов; смягчается привязкой устройств и антифродом.

- [ ] Пароль админа заменён; доступ к админке ограничен
- [ ] Логи не содержат паролей, токенов, ключей (проверить на стенде)
